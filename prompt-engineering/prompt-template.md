# Prompt 正文

## 【任务】

你负责 [一句话说明当前节点真正要解决的问题]。

你的目标是：

[用 1～3 句话说明模型最终需要得到什么语义结果。]

本节点只负责：

- [核心职责 1]
- [核心职责 2]
- [核心职责 3]

本节点不负责：

- [容易越权到的下游任务 1]
- [容易越权到的下游任务 2]
- [容易造成语义污染的任务]

> 不要描述整个系统怎么运行，只告诉模型当前这一步需要解决什么。

---

## 【上下文数据】

> 只有当前任务确实需要外部资料、长文本、检索结果、历史上下文时才保留本节。

[资料 / 原文 / 候选项 / 检索结果等]

如果有多种输入类型，说明它们在语义上的作用：

- `[字段 A]`：表示……
- `[字段 B]`：用于……
- `[字段 C]`：只是背景，不代表……

不要解释：

- Python 怎么产生这些字段
- 下游什么时候删除这些字段
- 数据库存储方式
- 与当前判断无关的工程实现

---

## 【核心语义原则】

> 这是 Prompt 最重要的部分。只写真正影响模型判断的业务规则。

### 1. 默认判断原则

默认：

[模型在模糊情况下应该采用什么方向]

例如：

- 默认不扩展到输入范围之外的新事项。
- 默认同一业务事项合并处理，只有明确独立事件才拆分。
- 证据不足时不自行补全。
- 只提取材料明确支持的事实。

### 2. 什么情况属于目标结果

满足以下语义条件时：

- [条件 1]
- [条件 2]
- [条件 3]

可以判断为：

[目标事件 / 分类 / 结果]

### 3. 什么情况不属于目标结果

以下情况不要判断为目标结果：

- [反例类型 1]
- [反例类型 2]
- [反例类型 3]

优先描述"为什么语义上不属于"，而不是列大量程序性禁止项。

### 4. 粒度 / 合并 / 拆分原则

如果当前任务涉及事件、观点、问题、主题等粒度判断，明确默认粒度。

例如：

> 顶层单位是一条可以独立成立的业务事项，而不是单个数字、动作或句子。

以下情况默认属于同一结果：

- [场景]
- [场景]

只有满足以下条件才拆分：

- [真正能够独立成立的条件]

不要针对每一种 bad case 分别增加规则，优先总结更高层的统一原则。

---

## 【证据与上下文使用规则】

> 只有任务存在证据绑定、RAG、长文本或多来源信息时保留。

### 核心判断可以使用什么证据

[例如：核心事实必须由 anchor 直接支持]

### 补充信息可以使用什么证据

[例如：允许从全文补充同一事项的事实]

### 不允许怎样使用上下文

例如：

- 不得用背景信息替代核心证据。
- 不得把另一个独立事项并入当前结果。
- 不得根据外部常识补齐材料中没有的信息。
- 多来源冲突时按 [具体语义原则] 处理。

程序可以验证的 sentence id 数量、ID 格式等不要写在这里。

---

## 【特殊业务边界】

> 只有真正无法被上面的统一原则覆盖，而且生产中经常误判的情况才写。

### 场景 A

当 [条件] 时：

[应该如何理解]

### 场景 B

当 [条件] 时：

[应该如何理解]

控制数量。如果特殊规则越来越多，应优先重新检查：

> 是否缺少一个更高层的统一原则？

而不是继续叠补丁。

---

## 【判断步骤】

> 可选。只有任务确实需要多步判断时保留。
> 不要求模型输出完整思维过程，只规定内部判断顺序。

在输出结果前，依次确认：

1. 当前输入真正描述的对象 / 事项是什么？
2. 是否满足目标语义定义？
3. 是否命中明确排除条件？
4. 是否与其他事实属于同一个语义单位？
5. 是否存在证据不足、背景混入或过度推断？
6. 最终只保留完成当前节点任务所需的信息。

只输出最终结果，不输出内部分析过程。

---

## 【输出内容】

> 这里只描述"模型需要表达什么"，不是写完整 Schema。

输出应包含：

- [真正需要模型生成的语义字段 1]
- [真正需要模型生成的语义字段 2]
- [真正需要模型生成的语义字段 3]

不要要求模型重复生成可以从已有结果推导出的信息。

具体 JSON Schema、字段类型、长度、枚举、数量限制优先由 structured output / 代码控制。

---

## 【Few-shot】

> 可选。默认不放。
> 只有规则本身无法稳定表达边界，或者生产中模型反复在某类场景出错时才增加。

Few-shot 优先使用"容易混淆的对照案例"。

### 示例 1：应当判断为目标结果

【输入】

[真实或高度接近真实的数据]

【正确结果】

[结果]

【边界说明】

[一句话说明真正需要模型学会的语义区别]

### 示例 2：看起来类似，但不应判断为目标结果

【输入】

[...]

【正确结果】

[...]

【边界说明】

[...]

原则：

- 少量高价值示例优于大量普通正例。
- 正文已经能明确表达的规则不需要再用示例重复。
- Few-shot 不得与正文规则冲突。
- 旧 prompt 调整后要重新检查旧 Few-shot 是否仍然成立。
