# 链路地图模板

链路地图记录一条业务链路的代码位置和衔接方式，帮助后来者少读无关代码。它是导航，不是证据：与代码不一致时以代码为准。

## 写什么
- 入口、调用顺序、数据交接、失败与恢复、已确认的坑，用 `路径::符号` 引用（路径相对项目约定的代码根，符号为函数/类/常量名），不写行号。
- 业务约束只写由谁实现、管什么，不抄具体取值；Prompt 写角色名或目录及加载位置，不写版本号。
- 每条事实都要读过对应代码；没读到或靠推断的放「待确认」。
- 不写代码和 Prompt 正文、Schema 全表、单次 bad case、运行数据、修改经过。
- 建议 120 行左右，不为行数遗漏关键逻辑。

## 基线与检查
- 「源码核对基线」填核对时已存在的提交号（与代码同批修改时填修改前的 HEAD）；只在列出的改动都核对过后推进。
- 「变化关注路径」包含地图引用的文件，以及这条链路用到的配置、settings、Schema 和 Prompt 角色目录；发现漏列的依赖时补进去。

## 模板

# <链路业务名>
范围：<从哪一步到哪一步>；不含：<…>（见 <另一份地图>）
源码核对基线：<commit>（<YYYY-MM-DD>）
核对覆盖：<已核对部分>；未核对：<…>
外部依赖（Git 看不到）：<检索服务、外部接口、.env 配置项；没有写"无">

检查（在代码根执行）：
```powershell
$b = '<源码核对基线>'
$p = '<引用文件>', '<配置与 settings>', '<Prompt 角色目录>'
git log --oneline "$b..HEAD" -- $p
git diff $b -U0 -- $p | Select-String '^@@'
git status --short --untracked-files=all -- $p
```
