## Working with this project

- Read the existing files before changing them, and build on the project's existing design system and components.
- When the user-facing text needs explanation, write it in full; do not leave it terse.

## Visual quality

- For new or redesigned UI, aim for a polished, cohesive result: clear visual hierarchy, intentional typography, balanced spacing, and consistent component states.
- Make in-scope controls perform their intended actions with visible feedback. Use subtle, purposeful motion to clarify relevant state changes and transitions.
- Adapt these choices to the project's existing design system and respect reduced-motion preferences.
- For new UI without an established design system or an explicit visual direction, favor an Apple-inspired aesthetic.

## Final constraints

- Do not replace or simplify the existing design system unless asked.
- Do not rewrite existing user-facing copy unless asked.
